# VitalRoot 작업 로그 (WorkLog)

## [2026-09-20] 출발지 핀 기반 코스 재도출, 대중교통/도보 듀얼 길찾기, 브라우저 QA 버그 패치

### 1. 작업 개요
- 사용자가 지도에 집(출발지) 핀을 설정했을 때, 거리 기준으로 가장 가까운 웰니스 코스 자동 재정렬 및 매칭.
- 사용자와 코스 시작점(안심식당) 간의 거리가 도보 5분(400m)을 초과할 경우, 네이버 지도 대중교통(버스/지하철) 길찾기 버튼(`/-/transit`)과 도보 버튼(`/-/walk`)을 함께 제공.
- 가상 브라우저 테스팅(/browser)을 통한 실제 웹 상호작용 검증 및 새로고침 시 사용자 위치 정렬 풀림 버그 패치.

### 2. 주요 변경 사항
1. **위치 동기화 및 코스 정렬 결함 수정 (`src/store/wellnessStore.ts`)**
   - 로그인된 프로필 동기화 함수(`syncProfileWithDb`) 호출 시, 설정된 `userLocation`과 `courseMode`를 무시하고 기본 데이터 순서로 덮어쓰던 결함 해결.
   - `computeFilteredCourses(courses, loadedProfile.chronicConditions, userLocation, courseMode)`로 전달하여 새로고침 후에도 사용자 핀 위치 기준 거리 정렬이 완벽하게 유지되도록 수정.

2. **사용자 핀 위치(달미역/선부동) 초근접 코스 신설 (`src/config/wellnessData.ts`)**
   - 신설 코스 `course-ansan-4`: `[당뇨·고혈압케어] 선부 보약 쌈밥 (달미역점) ➔ 샛터공원 & 선부광장 완만 둘레길` (520m, 도보 15분, 완만 경사).
   - 사용자가 핀을 찍은 안산 선부동/달미역 위치(`37.346, 126.812`)에서 불과 **260m (도보 4분)** 거리에 위치하여 핀 설정 즉시 1순위 초근접 코스로 자동 매칭.

3. **5분(400m) 기준 대중교통/도보 듀얼 길찾기 버튼 연동**
   - `src/components/panels/ControlPanel.tsx` (좌측 패널):
     - `distFromUser > 400`: `[🚌 대중교통]`(`/-/transit`) 및 `[🚶 도보]`(`/-/walk`) 듀얼 버튼 동시 제공.
     - `distFromUser <= 400`: `[🟢 내 위치 ➔ 식당 (5분 이내 초근접)]` 도보 버튼 제공.
   - `src/components/map/MapContainer.tsx` (지도 하단 플로팅 바):
     - `distFromUserToRest > 400`: `[🚌 대중교통 길찾기]` 및 `[🚶 도보 길찾기]` 듀얼 버튼 제공.
     - 거리 안내 문구에 `(도보 5분 초과 • 대중교통 권장)` 또는 `(도보 5분 이내 초근접)` 명확히 표기.

### 3. 발견된 예외 사항 및 우회법 (Known Exceptions & Workarounds)
- **증상**: 네이버 지도 v5 URL 연동 시 한글 파라미터(예: '내 위치', 매장명) 인코딩 누락 시 모바일/일부 웹 브라우저에서 경로 검색 실패 현상 발생.
- **해결/우회법**: 모든 출발/도착지 명칭에 `encodeURIComponent`를 엄격히 적용하여 URI 규격 준수.
- **증상**: `userLocation`이 없는 비로그인/초기 상태에서 400m 대중교통 버튼을 노출하면 잘못된 상대 경로가 생성될 수 있음.
- **해결/우회법**: `userLocation && isTransitRecommended` 조건부를 엄격히 설정하여 사용자 위치가 설정된 경우에만 대중교통 분기가 활성화되도록 방어 로직 적용.
